# 数智学研智能体（CXY-Agent）

> CXY = 产（Industry）· 学（Academia）· 研（Research）
>
> 基于 AI Agent 与 Claw 等技术，实时掌握专业领域产、学、研动态信息的智能体。
> 帮助学生从「只学课本知识」拓展到「了解真实产业发展、技术与实践场景」，
> 培养具有数字化、智能化视野的新一代大学生。

## 一、项目简介

数智学研智能体面向高校师生，持续采集智能制造领域的产学研动态，
把**产业进展、企业项目、技术研究成果**更快地引入课堂和实验室，
帮助学生建立**岗位认知、工程能力和创新意识**：

- **产**：追踪产业动向、标杆实践与岗位需求，帮助学生建立产业认知；
- **研**：追踪前沿论文、科研成果与技术转化，把最新进展引入课堂和实验室；
- **学**：追踪专业建设、课程改革与产教融合动态，服务学生学习与成长。

## 二、要解决的三个问题

1. **解决「学用脱节」** —— 很多学生毕业后发现，课堂学的和企业要的不完全一样。
   产学研融合能把企业真实需求、行业标准和一线技术带进培养过程；
2. **让学生接触真实问题** —— 通过了解产业趋势、产业实践和场景，
   学生能提前经历「需求 → 方案 → 验证 → 落地」的完整链条；
3. **提升就业竞争力** —— 充分理解产业需求的学生，更容易理解岗位要求，
   在简历和面试中更能体现与实际产业结合的能力。

## 三、专业领域：智能制造

本智能体聚焦**智能制造**领域 —— 用人工智能赋能新型制造业，
三条信息线索与关键词章节一一对应，每周各推送一期：

| 信息线索 | 关注内容 | 关键词章节 | 排期 |
| --- | --- | --- | --- |
| 产 · 产业与实践 | 灯塔工厂、标杆企业、政策名单、产业信号 | `keyword.md` 第一章 | 每周二 |
| 研 · 技术与科研 | 工业大模型、AI质检、预测性维护、机器人、工业软件 | `keyword.md` 第二章 | 每周四 |
| 学 · 大学学习 | 专业培养动态、竞赛实训、岗位招聘、学习检索式 | `keyword.md` 第三章 | 每周六 |

## 四、智能体核心机制

1. **关键词驱动的闭环采集** —— 基于 `keyword.md` 指定的关键字构成智能体的上下文，
   实现无人工干预的智能化逻辑闭环，持续提升内容检索的相关性；
2. **多维度量化价值终评** —— 改变传统关键词匹配的死板筛选，
   利用大模型从四个可调权重维度对产、学、研内容进行多视角、深度的量化打分：
   相关性（30%）、创新性（25%）、证据强度（25%）、可行动性（20%）；
3. **内容去重与事件聚合** —— 识别标题不同但内容高度相似的文章只保留一篇；
   基于 `event_key` 将同一事件的多个参考来源智能聚合后推送。

### 采集-评估-推送管线

```text
RSS 源 + Google News 检索式 + RSSHub
        │  （检索式由 keyword.md 的「主体词 × 信号词」原则生成，见 config.yaml）
        ▼
① 时间窗口过滤（近 7 天）→ ② 多层去重（URL / 标题相似度 / 正文指纹 / 历史已推事件）
        ▼
③ DeepSeek 粗筛（仅标题+摘要，注入 keyword.md 当日章节上下文）
        ▼
④ 补抓候选正文 → 正文指纹去重（标题不同的转载稿）
        ▼
⑤ DeepSeek 四维价值终评（相关性/创新性/证据强度/可行动性，本地按权重重算总分）
   + 生成 event_key，同一事件合并为一张卡片，与近期已推事件跨次去重
        ▼
⑥ 中文摘要（面向学生，点明与产业实践/技术前沿/学习就业的关联）+ 周度趋势观察
        ▼
⑦ Markdown 落盘 output/ → PushPlus 推送微信 → 状态记录 state/（防重复推送）
```

## 五、关键词体系

关键词配置见 [`keyword.md`](keyword.md)，是整个智能体的「信息视野」开关：

- **分三章组织**：产业与实践（产）、技术与科研进展（研）、大学阶段学习关注点（学）；
- **选词求准不求全**：只收「可独立检索」的具体词（灯塔工厂、工业大模型、西门子杯），不收泛词（机器学习、发布会）；
- **组合检索**：智能体按「主体词 × 信号词」生成检索式（如「灯塔工厂」×「新增名单」），降低噪音、提高命中精度；
- **优先级标注**：★★★ 核心必采、★★ 重要、★ 一般；
- **开箱即改**：编辑保存后，下次采集自动生效，无需修改代码——智能体每次运行时重新读取该文件并注入模型上下文。

设置关键词的核心目的：**让学生可以及时检索到关键、有用的信息**。

## 六、系统实现与运行

### 目录结构

```text
CXY-Agent/
├── README.md                 # 项目说明（本文件）
├── keyword.md                # 产学研情报采集关键词配置（智能体的"信息视野"）
├── config.yaml               # 排期 / 检索式 / RSS 源 / 四维权重 / 推送参数
├── cxy_agent/                # 智能体 Python 包
│   ├── main.py               # 编排入口（排期→采集→评估→推送）
│   ├── sources.py            # 检索系统：RSS / Google News / RSSHub 采集 + 多层去重
│   ├── filter.py             # 评估系统：DeepSeek 粗筛 / 四维终评 / 事件聚合 / 摘要
│   ├── push.py               # 推送系统：PushPlus 微信推送
│   └── state.py              # 已推送文章与事件历史（防重复）
├── tests/                    # 离线单元测试
├── output/                   # 每期简报落盘（Markdown）
├── state/                    # 运行状态（sent.json / events.json）
└── .github/workflows/daily.yml  # GitHub Actions 定时排期
```

### 环境变量

| 变量 | 用途 |
| --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥（粗筛、终评、摘要） |
| `PUSHPLUS_TOKEN` | PushPlus 推送 token（微信「推送加」公众号） |

### 本地运行

```bash
pip install -r requirements.txt

python -m cxy_agent.main --test-push            # 只验证微信推送通道
python -m cxy_agent.main --category research --dry-run  # 手动跑「研」板块,不实际推送
python -m cxy_agent.main --weekday 1            # 模拟周二（产·产业实践）
python -m cxy_agent.main --skip-if-ran-today    # 兜底补跑（当日已推过则跳过）
```

### GitHub Actions 自动运行

1. 把本仓库推到 GitHub；
2. 在仓库 **Settings → Secrets and variables → Actions** 添加 `DEEPSEEK_API_KEY` 与 `PUSHPLUS_TOKEN`；
3. 工作流按北京时间 **周二/周四/周六 12:00** 自动运行对应板块（另有 16:30 兜底梯队，当日已推则静默跳过）；
4. 每次运行后 `state/` 与 `output/` 自动提交回仓库，实现跨次去重与简报归档。

### 调整信息视野

- 改**关注什么**：编辑 `keyword.md`（章节结构不要动，`##` 标题含「第一章/第二章/第三章」用于板块匹配）；
- 改**怎么搜、推多少**：编辑 `config.yaml`（检索式、RSS 源、四维权重、`min_score`、`max_articles`、排期）。

# CXY-Agent · 数智学研智能体

产学研情报闭环采集智能体：每次采集时读取仓库根目录的 [`keyword.md`](./keyword.md)，
将关键字注入检索上下文，自动完成「检索 → 过滤 → 评分 → 日报」全流程，
实现无人工干预的闭环采集。用户只需维护 `keyword.md`，编辑保存后下次采集自动生效。

## 工作原理

```
keyword.md（用户维护）
      │ 每次采集时拉取最新版
      ▼
agent/keyword_parser.py   解析领域/产/学/研/政策关键字、排除词、采集偏好
      ▼
agent/queries.py          展开为检索计划（主体词 × 事件词，按优先级配额）
      ▼
采集层（Kimi Work 定时任务） 按计划逐条检索，收集候选情报条目
      ▼
agent/scoring.py          排除词过滤 + 三因子评分（相关性 30% / 时效 40% / 来源 30%）
      ▼
agent/report.py           生成中文 Markdown 情报日报 → reports/
```

## 目录结构

```
├── keyword.md        # 检索配置（用户直接维护，唯一需要动的文件）
├── agent/            # 核心库：解析 / 查询 / 评分 / 报告
├── AUTOMATION.md     # 定时采集任务执行手册（智能体每次运行时阅读）
└── reports/          # 产出的情报日报（按日期归档）
```

## 本地自检

```bash
python -m agent summary   # 解析配置并打印摘要
python -m agent plan      # 打印本次采集的检索计划
```

## 闭环运行

由 Kimi Work 定时任务驱动，详见 [AUTOMATION.md](./AUTOMATION.md)。
任务每次运行时：拉取最新 `keyword.md` → 生成检索计划 → 逐条检索近 7 天情报 →
排除词过滤 → 评分排序 → 输出 `reports/YYYY-MM-DD.md` 并在会话中给出要点摘要。

## 维护关键字

见 `keyword.md` 第一节「维护指南」。要点：

- 新增：在对应分类下以 `- ` 开头另起一行；同义词用 `、` 分隔；
- 优先级：行尾加 ★（★★★ 核心必采 / ★★ 重要 / ★ 一般）；
- 屏蔽：把不想看到的词写入「七、排除词」，命中即丢弃；
- 保留所有 `##` / `###` 标题与列表格式，解析器依赖该结构。
